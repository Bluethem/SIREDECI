# 19. Pruebas Unitarias

Este documento detalla la configuración y el uso de las pruebas unitarias en SIREDECI.
En esta fase nos centraremos en las secciones **19.1 (configuración)** y **19.2 (backend)**.

## 19.1. Configuración de Frameworks {#configuracion}

### 19.1.1. Backend – pytest y pytest-django

SIREDECI utiliza **pytest** como framework principal de pruebas para el backend Django.

- Archivo de configuración principal: `backend/pytest.ini`

Ejemplo actual:

```ini
[pytest]
DJANGO_SETTINGS_MODULE = config.settings.direct
python_files = tests.py test_*.py *_test.py
```

- Fixtures globales: `backend/conftest.py`
  - Fixture `django_db_use_migrations` para evitar problemas con migraciones en tests.
  - Fixture `usuario_interno` para crear un usuario interno con rol válido (por ejemplo `ROL-001`).

### 19.1.2. Cómo ejecutar las pruebas de backend

Desde la carpeta `backend` con el entorno virtual activado:

```bash
pytest                 # Ejecuta todos los tests
pytest tests/          # Ejecuta solo la carpeta tests
pytest tests/test_notificaciones_usuario.py  # Ejecuta un archivo concreto
```

Recomendaciones:

- Ejecutar primero archivos concretos cuando se agregan nuevos tests.
- Usar la opción `-vv` para ver más detalle en caso de fallo.

### 19.1.3. Organización de los archivos de pruebas

Se recomienda seguir esta estructura dentro de `backend/`:

- Carpeta general de tests: `backend/tests/`
- Un archivo por módulo o familia de funcionalidades:
  - `test_notificaciones_usuario.py`
  - `test_notificaciones_ciudadano.py`
  - `test_denuncias_ciudadano.py`
  - `test_estadisticas_publicas.py`
  - etc.

Cada archivo debe agrupar tests relacionados, usando nombres descriptivos para las funciones de prueba.

### 19.2.3. Patrón recomendado para los tests de endpoints

- Usar `APIClient` de `rest_framework.test`:

```python
import pytest
from rest_framework.test import APIClient


@pytest.mark.django_db
def test_ejemplo_endpoint(usuario_interno):
    client = APIClient()
    client.force_authenticate(user=usuario_interno)

    response = client.get("/api/notificaciones/usuario/")

    assert response.status_code == 200
    data = response.json()
    assert "results" in data
```

- Para endpoints públicos (sin autenticación), no es necesario `force_authenticate`, solo se usa `client = APIClient()`.

### 19.2.4. Criterios de aceptación para esta fase

Consideraremos completada esta fase de pruebas unitarias de backend cuando:

- Existan tests automatizados para **notificaciones internas**, **notificaciones de ciudadano** y al menos un
  módulo adicional (p. ej. estadísticas públicas o denuncias).
- `pytest` se ejecute sin errores desde la carpeta `backend`.
- Haya documentación mínima de:
  - Cómo ejecutar los tests.
  - Qué módulos están cubiertos.
