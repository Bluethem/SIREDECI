# Documentación del Código

Esta sección describe cómo se ha documentado el código fuente de **SIREDECI**
en sus distintas capas (backend y frontend), así como los lineamientos
generales para mantener la calidad de la base de código.

---

## Guías Generales

- Uso consistente de **inglés para nombres técnicos** (clases, métodos,
  variables) y **español para textos de interfaz** y mensajes al usuario.
- Nombres descriptivos para modelos, vistas y componentes (por ejemplo,
  `CiudadanoLoginView`, `RegistrarDenuncia.vue`, `MisDenuncias.vue`).
- Estructuras de directorios alineadas con la arquitectura por dominios
  (usuarios, ciudadanos, denuncias, reportes, etc.).

---

## Backend (Django)

- **Estructura de aplicaciones:**
  - Código organizado en `backend/apps/` por dominios: `usuarios`,
    `ciudadanos`, `denuncias`, `personal`, `notificaciones`,
    `reportes`, `categorias`.
  - Cada app contiene sus propios `models.py`, `serializers.py`, `views.py` y
    `urls.py` cuando aplica.

- **Comentarios y docstrings:**
  - Se añaden comentarios breves en puntos de lógica compleja (por ejemplo,
    creación de denuncias y asignaciones, cálculo de indicadores).
  - Las vistas y serializers clave incluyen docstrings para explicar el
    propósito del endpoint.

- **Archivos de configuración:**
  - `config/settings/base.py`, `development.py`, `production.py` y
    `direct.py` documentan explícitamente su propósito (entorno general vs
    configuración directa para debugging/deploy en Render).
  - Uso de variables de entorno documentado en `3.2-configuracion-entorno.md`.

---

## Frontend (Vue 3)

- **Organización por vistas:**
  - `src/views/ciudadano/`, `src/views/municipal/`, `src/views/admin/` y
    `src/views/public/` agrupan las pantallas por tipo de usuario.
  - `src/components/` contiene componentes reutilizables como barras de
    navegación (`NavbarCiudadano.vue`, `NavbarPublico.vue`).

- **Estilo de componentes:**
  - Se utiliza la Composition API (`<script setup>`) para componentes
    principales.
  - Los nombres de propiedades y estados siguen un patrón claro (`currentStep`,
    `selectedCategory`, `denunciasFiltradas`, etc.).

- **Servicios HTTP:**
  - `src/services/` concentra la interacción con la API (`auth.js`,
    `denuncias.js`, `api.js`).
  - Cada servicio documenta las rutas utilizadas (`/api/denuncias/`,
    `/api/public/reportes/...`) y agrupa las funciones relacionadas.

---

## Pruebas y Documentación Asociada

- Las pruebas unitarias de backend se documentan en
  `4-pruebas/4.2-pruebas-unitarias.md` (secciones de backend).
- Las pruebas unitarias de frontend se documentan en la misma sección para los
  componentes priorizados (login de ciudadano, registro de denuncias, mis
  denuncias, estadísticas públicas).
- Cada archivo de test en `frontend/tests/` incluye un comentario breve sobre
  el alcance del caso de prueba.
