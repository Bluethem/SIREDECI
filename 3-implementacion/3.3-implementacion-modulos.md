# Implementación de Módulos

En esta sección se describe cómo se implementaron los módulos principales de la
aplicación **SIREDECI**, tanto en el backend (Django REST Framework) como en el
frontend (Vue 3 + Vite + Vuetify/Tailwind).

---

## Backend

El backend se estructura en aplicaciones Django independientes ubicadas en
`backend/apps/`, cada una encargada de un dominio funcional concreto.

### a) Módulo de Usuarios y Roles (`apps.usuarios`)

- Implementa el modelo `Usuario` con un manager personalizado.
- Campos clave: `email`, `nombre_usuario`, datos personales básicos y estados.
- Se utiliza el sistema de autenticación de Django + permisos propios
  (por ejemplo, permiso `IsStaffLike` para usuarios internos).
- Los usuarios internos se relacionan con otros módulos, como
  `PersonalMunicipal` y generación de reportes.

### b) Módulo de Ciudadanos (`apps.ciudadanos`)

- Modelo `Ciudadano` con campos como `dni`, `nombre`, `apellido`, `email` y
  `fecha_emision_dni`.
- Vista `CiudadanoLoginView` para autenticación de ciudadanos por DNI y fecha de
  emisión.
- Genera un token de sesión simple (`session_token`) que se devuelve al
  frontend y se usa para identificar al ciudadano en las operaciones de
  denuncias y notificaciones.

### c) Módulo de Categorías y Áreas Responsables (`apps.categorias`)

- Modelo `AreaResponsable` que representa las áreas municipales que atienden
  denuncias (ej. Limpieza Pública, Alumbrado, etc.).
- Modelo `Categoria` que se asocia a un `AreaResponsable` y clasifica las
  denuncias.
- Es un módulo transversal utilizado por `Denuncia`, `PersonalMunicipal` y
  los reportes.

### d) Módulo de Denuncias (`apps.denuncias`)

- Modelo principal `Denuncia` con campos como:
  - `titulo`, `descripcion`, `id_categoria`, `id_ciudadano`, `es_anonima`,
    `prioridad`, `id_ubicacion`, `numero_seguimiento`.
- Serializador `DenunciaCreateSerializer` que encapsula la lógica de creación:
  - Valida la presencia de `id_ciudadano` cuando la denuncia no es anónima.
  - Crea internamente la `Ubicacion` y posibles evidencias adjuntas.
- `DenunciaViewSet` expone endpoints REST:
  - `/api/denuncias/` para registro de nuevas denuncias.
  - `/api/denuncias/mis-denuncias/` para que un ciudadano consulte solo sus
    denuncias.
- Este módulo es la base de la mayoría de flujos funcionales de la aplicación.

### e) Módulo de Notificaciones (`apps.notificaciones`)

- Gestiona las notificaciones internas para usuarios y las notificaciones
  dirigidas a ciudadanos.
- Expone endpoints para listar notificaciones y actualizar preferencias de
  notificación.
- Se integra con el módulo de usuarios y con el flujo de denuncias para
  informar cambios de estado.

### f) Módulo de Reportes y Estadísticas (`apps.reportes`)

- Modelos principales:
  - `Reporte` (reportes generados),
  - `Dashboard`,
  - `TendenciaGeografica`,
  - `RankingDesempeno`.
- Endpoints internos (admin) bajo `/api/reportes/`:
  - `indicators/` para indicadores clave.
  - `desempeno/ranking/` para ranking de áreas responsables.
  - `dashboard/summary/` para el resumen del panel de administración.
- Endpoints públicos bajo `/api/public/reportes/` (archivo
  `apps.reportes.public_urls`):
  - `/estadisticas/denuncias-resumen/` con datos agregados de denuncias.
  - `/tendencias-geograficas/` con análisis por distrito.
  - `/ranking-areas/` con desempeño de áreas responsables.
- Utiliza permisos diferenciados: `AllowAny` para endpoints públicos y
  `IsAuthenticated + IsStaffLike` para reportes internos.

### g) Módulo de Personal Municipal (`apps.personal`)

- Modelo `PersonalMunicipal` que vincula un `Usuario` interno con un área
  responsable (`AreaResponsable`).
- Modelo `Asignacion` que relaciona una `Denuncia` con una persona municipal y
  tiene un estado `es_activa` para saber si la asignación está vigente.
- Vistas clave:
  - `/api/municipal/mis-denuncias/`: lista denuncias asignadas al personal
    autenticado.
  - `/api/municipal/pendientes-asignar/`: lista denuncias sin asignación activa
    para el área del personal.
- Requiere autenticación y el permiso `IsStaffLike`, además de verificar que el
  usuario tenga un `PersonalMunicipal` activo.

## Frontend

El frontend se implementa con **Vue 3 (Composition API)**, **Vite** como
bundler y componentes de UI modernos (Tailwind/Vuetify). El código se organiza
principalmente en:

- `src/views/ciudadano/`
- `src/views/admin/`
- `src/views/municipal/`
- `src/views/public/`
- `src/components/` (componentes reutilizables como barras de navegación y
  tablas)
- `src/services/` (clientes HTTP para hablar con la API REST)

### a) Módulo Ciudadano (frontend)

Vistas principales:

- `LoginCiudadano.vue`
  - Formulario de login con `dni` y `fecha_emision`.
  - Llama a `authService.loginCiudadano` y guarda la sesión del ciudadano
    (incluyendo `id_ciudadano`) en `localStorage`.

- `DashboardCiudadano.vue`
  - Pantalla de bienvenida tras el login.
  - Muestra accesos rápidos a registrar denuncia, ver mis denuncias y ver
    estadísticas públicas.

- `RegistrarDenuncia.vue`
  - Flujo guiado por pasos:
    - Selección de categoría (asociada a `AreaResponsable`).
    - Detalle de la denuncia (título, descripción).
    - Ubicación en mapa (Leaflet) y evidencias (imágenes).
    - Confirmación y envío.
  - Llama a `denunciasService.crearDenuncia` enviando `id_ciudadano` y datos de
    ubicación.

- `MisDenuncias.vue`
  - Lista las denuncias del ciudadano utilizando
    `denunciasService.getMisDenuncias`.
  - Permite filtrar por estado y buscar por código o título.
  - Usa tarjetas con chips de estado y prioridad.

- `EstadisticasPublicas.vue`
  - Consume los endpoints públicos
    `/public/reportes/estadisticas/denuncias-resumen/`,
    `/public/reportes/tendencias-geograficas/` y `/public/reportes/ranking-areas/`.
  - Muestra tarjetas de métricas, listados por categoría, estado y distritos, y
    el ranking de áreas responsables.

### b) Módulo Admin (frontend)

Vistas ubicadas en `src/views/admin/`:

- `DashboardAdmin.vue`
  - Muestra KPIs generales para la administración (totales, tendencias,
    tarjetas de estado, etc.).
  - Consume endpoints internos de reportes bajo `/api/reportes/...` a través de
    un cliente Axios con `baseURL` configurado.

- `Indicadores.vue`
  - Lista y visualiza indicadores definidos en el backend (`Indicador`).
  - Permite al personal administrativo monitorear el desempeño global.

- `RankingDesempeno.vue`
  - Muestra el ranking de desempeño de áreas responsables.
  - Se alimenta del endpoint `/api/reportes/desempeno/ranking/`.

- `ReportesHub.vue` y `VistaPreviaReportes.vue`
  - Pantallas para gestionar distintos tipos de reportes internos y
    previsualizarlos/descargarlos.

### c) Módulo Municipal (frontend)

Vistas ubicadas en `src/views/municipal/`:

- `LoginAdmin.vue` (o vista equivalente para personal interno)
  - Formulario de acceso para personal municipal/administrativo.
  - Establece la sesión interna y los roles disponibles.

- `DashboardArea.vue`
  - Tablero específico para un área responsable.
  - Muestra las denuncias asociadas y métricas filtradas por área.

- `PendientesAsignar.vue` y `MiAreaAsignadas.vue`
  - `PendientesAsignar.vue` consume `/api/municipal/pendientes-asignar/` para
    mostrar denuncias sin asignación activa en el área.
  - `MiAreaAsignadas.vue` consume `/api/municipal/mis-denuncias/` para mostrar
    denuncias ya asignadas al personal autenticado.

### d) Vistas Públicas y Componentes Compartidos

- `src/views/public/EstadisticasPublicas.vue` y `ReportesPublicos.vue` para
  acceso ciudadano sin autenticación a estadísticas y reportes.
- `src/components/NavbarPublico.vue` y `NavbarCiudadano.vue` proporcionan la
  navegación superior, adaptando enlaces según sea público o ciudadano
  autenticado.
- Servicios HTTP en `src/services/`:
  - `auth.js`: login de ciudadano y de usuarios internos.
  - `denuncias.js`: operaciones sobre denuncias.
  - `publicReportes`/`api.js`: cliente genérico Axios con `baseURL` y
    configuración común.
